# Deep Audit — 2026-08-13

Five-track audit (rules engine, playability, code quality, test coverage, performance). Baseline: build clean, oxlint clean, 476 tests pass. Every finding below was verified against source; the three flagship claims were additionally verified by direct code trace and an empirical simulation (AI attack double-fire reproduced, then the throwaway harness was removed). Repo is untouched.

### Batch 3 (performance) — landed
**Baseline after batch 3: 499 client tests, 84 server tests, tsc + oxlint + build clean.**

- **Persistence debounced** (`gameStore.ts`) — a full-board `JSON.stringify` + backgrounds IndexedDB write previously ran on *every* store update (an AI turn ≈ 15 writes). ### Batch 5 (AI-turn undo soft-lock + pollution) — landed
**Baseline after batch 5: 534 root tests (+1), server tests pass, tsc + oxlint + build clean.**

### Batch 15 (scoped priority: player response windows) — landed

## ORIGINAL FINDINGS

## CRITICAL — game-breaking, user-visible immediately

### 1. "Discard to 7" counts both players' hands — the player discards their entire hand every turn
- `advanceTurn`, `announceEndTurn`, and `discardForTurn` compute hand size as `state.cards.filter((c) => c.zone === 'hand').length` with **no owner filter** — `src/stores/gameTurnPhases.ts:13`, `:95`, `:185`.
- The AI always holds 7, so the player's ≤7-card hand always trips `handSize > 7`; they must discard down to 0 before the turn hands off. The AI's own cleanup (`gameOpponentAI.ts:361-371`) is correctly owner-scoped, so only the player is affected.
- **Repro:** any game vs AI, end your turn with a legal 7-card hand → forced discard prompt; discard everything.

### 2. `deal_damage` amount is never parsed — every damage-dealing ability deals exactly 1
- `parseEffect` has no amount extraction for `deal_damage` (matches at `scripts/parse-card-rules.mjs:434`), so `params` is always `{}`; resolution defaults to `(params.amount as number) ?? 1` — `src/stores/triggerActions.ts:132`, `:381`.
- Every burn spell in all 16 decks deals 1: Lightning Bolt ("deals 3"), Blasphemous Act ("deals 13"), Fury (4), etc.
- **Repro:** cast Lightning Bolt on a 2/2 — it survives with 1 damage marked.

### 3. Untargeted damage/trigger resolution never runs state-based actions — mass damage kills nothing
- The untargeted `deal_damage` branch of `resolveTrigger` applies damage but never calls `checkStateBasedActions` — `src/stores/triggerActions.ts:128-136`. Only the targeted path (`:398`) and combat run SBA.
- **Repro:** resolve "deals 3 damage to each creature" → every 2/2 survives with 3 damage marked until some unrelated SBA runs.

### 4. AI attack triggers fire twice (empirically confirmed)
- The AI resolves attack triggers directly via `resolveAIAutoAbilities(attacker, 'attack')` (`src/stores/gameOpponentAI.ts:339-341`), then `resolveCombat` emits an `attack` event (`src/stores/gameCombatActions.ts:112-114`) which queues the same triggers again, resolved by `resolveAITriggerInstances` (`gameOpponentAI.ts:356-357`).
- **Verified empirically:** an Annihilator 2 AI attacker sacrificed **4** permanents instead of 2.
- **Repro:** AI attacks with Ulamog's Crusher / It That Betrays → player sacrifices 4, not 2. Goldspan Dragon double-creates Treasure.

## HIGH — severely broken or pervasive

### 5. Land plays bypass the rules pipeline: enters-tapped ignored + no landfall event
- The hand-click play path (`src/stores/gameDeckActions.ts:205-216`) sets `zone:'battlefield', tapped:false` directly and only emits `etb`; the AI path (`gameOpponentAI.ts:251-262`) enters tapped only if its own rule check says so and emits nothing. The drag-drop path (`gameCardMovement.ts:90-97`) *does* emit `landfall` and respect entry rules — behavior differs by input method.
- Taplands (Smoldering Marsh, Rakdos Carnarium, Golgari Rot Farm, Path of Ancestry, …) enter untapped when clicked from the hand; landfall triggers never fire from the primary play path.

### 6. Tapped creatures can't block (both engines + AI)
- All blocking filters reject tapped creatures — `src/stores/gameCombatActions.ts:94`, `server/src/rooms/combat.ts:106`, `GameRoom.ts:214`, `opponentAI.ts:78`. MTG only requires a blocker to be untapped to *attack*.
- Your creatures tapped from your own attack can't block the AI's swing on its turn.

### 7. Blocked attacker whose blockers died in the first-strike step is treated as unblocked in the regular step
- `gameCombatActions.ts:172-224`: after first-strike SBA kills all of an attacker's blockers, `liveBlockers = []` triggers the unblocked branch — full damage to the player plus repeat lifelink/commander damage. Rules: the attacker is still blocked.
- **Repro:** double-strike attacker (e.g. Fury) vs a 2/2 → first-strike kills the blocker, then the regular step hits the player for full power.

### 8. Player cast count is off by one — breaks "first spell each turn" and storm
- The player's `cast` event sends `count: playerSpellsCastThisTurn + 1` after the counter already incremented (`src/stores/gameDeckActions.ts:230-235`); the AI path sends the value after increment (correct). `count === 1` never fires for the player, and storm copies (`count - 1`) are one too many.

### 9. +1/+1 counters increase toughness but not power
- `getCardPower` (`src/utils/misc.ts:41-43`) sums base + `powerBoost` but omits `counters`; `getCardToughness` includes them. A 1/1 with four +1/+1 counters computes as 1/5 in combat and AI decisions. The single `counters` field also conflates −1/−1 and loyalty, so a −1/−1 counter is a toughness *boost*.

### 10. `combat_damage` triggers can't identify the source — they fire on the opponent's damage too
- `buildTriggerInstances` only derives `eventCard` from `cardId`-keyed events (`src/stores/triggerEngine.ts:129-131`), but `combat_damage` carries `sourceCardId` (`src/types/card.ts:258`), so `eventCard` is undefined and every self/owner condition is skipped → Hapatra, Toski, Bident of Thassa, etc. fire on *either* side's combat damage.

### 11. Inflected-verb triggers never fire ("draws", "casts", "sacrifices", possessive upkeeps)
- Trigger patterns use exact word boundaries (`\bdraw\b`, `\bcast\b`, `\bsacrifice\b`) that fail on inflections; "each opponent's upkeep" fails the `(your|each|the) upkeep` patterns. Result: 328 triggered abilities across 264 cards land with `triggerEvent: null` and never register. Affected: Kederekt Parasite, Mayhem Devil, Mogis God of Slaughter, Mentor of the Meek, Harsh Mentor, Scaretiller, and more.

### 12. Multiplayer commander damage never registers (once cast, a commander is no longer in `command`)
- `GameRoom.resolveCombat` checks `attackerOwner?.command.some((c) => c.id === hit.attackerId)` (`server/src/rooms/GameRoom.ts:673-686`), but casting removes the card from `command` (`GameRoom.ts:466-490`). The 21-damage loss condition is dead in every multiplayer game.

### 13. Undo snapshots omit `gameOver`, `triggerStack`, `wardPrompt`, `auraPrompt`
- `takeSnapshot` (`src/stores/gameRules.ts:166-197`) never captures these; undo restores life after a loss but the game-over overlay stays; undoing a cast leaves the spell's triggers on the stack; ward/aura prompts survive undo.

### 14. MP server allows cheating card state — library→battlefield/hand, free casting
- `playCard` (`GameRoom.ts:82-97`) and the generic `moveCard` (`GameRoom.ts:121-135`) accept any owned card; `findPrivateCard` resolves library cards; nothing enforces spell costs (`addMana`/`spendMana` are free-form). LOOPS.md item 6.2 confirmed.

### 15. Solo vs MP combat math has already drifted
- Solo uses the parsed-rules keyword cache + static pumps (`gameCombatActions.ts:12-13`); the server regexes the first line of oracle text for keywords and ignores pumps/boosts (`server/src/rooms/combat.ts:26-52`). An anthem-boosted 2/2 blocks as 2/2 in MP.

### 16. Dead commander never returns to the command zone (and is lost on redeal)
- `checkStateBasedActions` (`src/stores/gameStateBasedActions.ts:29-47`) has no `isCommander` handling; no context-menu item can move a card to the command zone; `resetAndDealCards` only re-seats cards already there, so a dead commander shuffles into the library on redeal.

### 17. Undo after the opponent's turn soft-locks the game on the opponent's turn
- The AI's `advanceTurn` is wrapped as undoable (`gameStore.ts:425-439`); Ctrl+Z after the AI turn reverts `activePlayer` to `'opponent'` with no timers scheduled and the PhaseBar disabled for the opponent (`PhaseBar.tsx:66`). Game is stuck.

### 18. `create_token` requires singular `\btoken\b` — plural "tokens" never matches → 35 abilities are dead "other"
- `scripts/parse-card-rules.mjs:430` fails on "creature **tokens**". Grave Titan, Siege-Gang Commander, Worldspine Wurm, Myr Battlesphere, Deep Forest Hermit, Phyrexian Triniform, Treebeard, Farmer Cotton, Orchard Strider, Royal Warden, Imotekh all produce no tokens and toast "not implemented".

### 19. Drag/drop and command-zone click play cards for free
- `moveCard` (`src/stores/gameCardMovement.ts:19-63`) computes `canPayMana` but never checks it; dragging a creature from hand to battlefield, or clicking the commander in the command zone, bypasses the mana/tax check `castSpell` enforces (`gameRules.ts:49-51`).
